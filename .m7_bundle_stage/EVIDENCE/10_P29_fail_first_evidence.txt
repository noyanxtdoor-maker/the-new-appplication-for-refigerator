--------------------------------------------------------------------------------
TEST-AUTHORING CORRECTION — DISCLOSED
--------------------------------------------------------------------------------
The third test was CORRECTED during certification, and the correction made the
test STRONGER, not weaker. It was NOT weakened to make it green.

Original (defective) form: seeded a NON-recurring Event 7 days in the past and
asserted that an occurrence dated today resolves.

Why that was wrong: `CalendarRecurrenceFrequency.none` yields exactly ONE
occurrence. `CalendarRecurrenceRule.occurrenceIndexOn` implements:
    CalendarRecurrenceFrequency.none => targetDate == startDate ? 0 : null
So a non-recurring Event anchored 7 days ago can never produce a today-dated
occurrence. The assertion was unsatisfiable by ANY implementation, and the
failure was therefore a defective test, not an implementation bug.

Correction applied: seed a DAILY recurring series anchored 7 days back, and add
an optional `recurrence` parameter to the `seedEvent` helper. The test now
exercises the real scenario P29 targets — a genuinely recurring series whose
newest occurrence must still resolve after the anchor date has passed.

No assertion was relaxed. The remaining two tests are unchanged.

Import hygiene fix: removed an unused
`import 'package:rmplanner/core/time/app_clock.dart';` (FixedClock actually comes
from test/support/test_dependencies.dart). This was surfaced by the analyzer gate
and fixed by deletion, not by suppression.
