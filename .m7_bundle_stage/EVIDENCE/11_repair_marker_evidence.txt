--------------------------------------------------------------------------------
REQUIREMENT
--------------------------------------------------------------------------------
Event mutations must mark a transaction-local reminder repair request in the
SAME transaction, so that the marker commits atomically with the mutation and
rolls back with it. The marker must be idempotent per profile.

--------------------------------------------------------------------------------
IMPLEMENTATION
--------------------------------------------------------------------------------
NEW file: lib/core/background/reminder_recovery_request.dart

Stable key:
    static String stableKeyFor(String profileId) => 'reconcile:reminders:$profileId';

Writer (idempotent):
    Future<void> mark(DatabaseConnectionUser executor, {required String profileId}) async

Idempotency rule: when a marker row already exists for the profile, the existing
row's `state`, `attemptCount`, `snoozeCount`, `sourceRevision` and `createdAtUtc`
are PRESERVED. Only the queued/reconciliation intent is (re)asserted. This means
repeated Event edits cannot inflate the repair budget or reset retry history.

Row shape (written into the EXISTING background_work_requests table — NO schema
change; schema remains v46):
    stableKey            = reconcile:reminders:<profileId>
    category             = reminderRecovery
    ownerKind            = profile
    occurrenceId         = null
    platformNotificationId = null
    state                = queued

Call sites — the marker is written BEFORE writeGuard.beforeCommit(), i.e. inside
the same transaction:
    lib/features/planner/data/drift_calendar_event_repository.dart
      - create
      - edit
      - cancel
      - reschedule
      - duplicate
    Pattern at each site:
        await reminderRepair?.mark(database, profileId: profileId);
        await writeGuard.beforeCommit();
