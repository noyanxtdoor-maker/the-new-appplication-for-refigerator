--------------------------------------------------------------------------------
REQUIREMENT — DISPATCH IDENTITY
--------------------------------------------------------------------------------
Dispatch identity is the triple:
    (stableKey, normalized scheduled target, sourceRevision)
Retrying the SAME generation must PRESERVE the retry budget. A content-only
change must NOT replay a completed or uncertain generation. Transitions are
compare-and-swap (CAS). Superseded generations must produce ZERO posts.

--------------------------------------------------------------------------------
IMPLEMENTATION
--------------------------------------------------------------------------------
File: lib/core/background/workmanager_background_work_gateway.dart

Exactly three worker input fields are permitted — and exactly three are emitted:
    static const String stableKeyField         = 'stable_key';
    static const String scheduledUtcMsField    = 'scheduled_utc_ms';
    static const String sourceRevisionField    = 'source_revision';

    static const Set<String> allowedFields = <String>{
      stableKeyField,
      scheduledUtcMsField,
      sourceRevisionField,
    };

Strict parse — the input map is REJECTED outright unless it is exactly the
three-key set. There is no "ignore unknown keys" leniency:

    if (input == null || input.length != allowedFields.length) return null;
    if (input.keys.any((key) => !allowedFields.contains(key))) return null;
    final key       = input[stableKeyField];
    final scheduled = input[scheduledUtcMsField];
    final revision  = input[sourceRevisionField];
    ...
    if (!_stableKeyPattern.hasMatch(key)) return null;

Stable-key grammar (bounds the identifier; rejects arbitrary text):
    static final RegExp _stableKeyPattern = RegExp(r'^reminder:[A-Za-z0-9_.:-]{1,240}$');

Unique work naming (encodes the full dispatch identity so that a changed target
or a changed revision is a DISTINCT unit of work):
    nt.reminder.<platformId>.<utcMs>.<SHA256(revision)[0:16]>

WORKINFO STATE MATRIX
--------------------------------------------------------------------------------
File: lib/core/background/background_repair_decision.dart

Typed platform state, distinguishing absent / pending / terminal / unavailable:
    enum BackgroundRegistrationState { absent, pending, terminal, unavailable }

Two rules that the matrix enforces and that an independent reviewer should check
carefully, because they are where this milestone is easiest to get wrong:

1. UNKNOWN != ABSENT. An unreadable or unavailable WorkInfo must not be treated
   as proof that no work exists. Collapsing `unavailable` into `absent` would
   double-post: the delivery path would believe nothing is scheduled and enqueue
   a duplicate.

2. DURABLE ELIGIBILITY OUTRANKS WORKINFO. The durable eligibility record is
   authoritative over the platform's report of the work item. Android's own
   platform facts (from the review) are that ENQUEUED and BLOCKED collapse to
   `scheduled` — so WorkInfo alone cannot distinguish those cases, and the
   durable record must decide.

TRANSPORT OWNERSHIP AND STICKY MARKERS (Contract section 6 / 12)
--------------------------------------------------------------------------------
File: lib/features/notifications/application/reminder_reconciler.dart
    const String _workerTransportPrefix = 'm7w_';   // worker, STICKY
    const String _nativeTransportPrefix = 'm7n_';   // native, NOT sticky

A reminder owned by the native ordinary path (`m7n_`) stays on the native path.
Only the enriched WorkManager path (`m7w_`) is sticky. This prevents an ordinary
reminder from being silently migrated onto the worker transport.
