IMPLEMENTATION
  lib/core/background/workmanager_background_work_gateway.dart defines
  CanonicalReminderWorkSpec with EXACTLY three fields and a closed allowlist:
    stableKeyField         = 'stable_key'
    scheduledUtcMsField    = 'scheduled_utc_ms'
    sourceRevisionField    = 'source_revision'
    allowedFields = {stable_key, scheduled_utc_ms, source_revision}
  toInputData() emits exactly those three keys and nothing else.
  The parser enforces `input.length != allowedFields.length -> null` and
  `input.keys.any((k) => !allowedFields.contains(k)) -> null`, so any extra or
  unknown key is rejected as malformed.

WHAT IS PERSISTED (technical identifiers only)
  - stable_key: a logical reminder key of the form
      reminder:calendarEvent:<profileId>:<occurrenceId>:base
      reminder:task:<profileId>:task:<taskId>:<projectedDate>:base
    constrained by RegExp ^reminder:[A-Za-z0-9_.:-]{1,240}$ — identifiers,
    never display text.
  - scheduled_utc_ms: an integer UTC millisecond target.
  - source_revision: a technical revision token (IDs, timestamps, version
    tokens, and the m7w_/m7n_ transport marker), constrained by
    ^[A-Za-z0-9_.:-]{1,256}$.
  - Unique work name: nt.reminder.<platformId>.<utcMs>.<SHA256(revision)[0:16]>
    — a technical digest, never a hash of private text. No displayTitle
    hashCode and no hash of name/notes/location is used for new M7 work.

WHAT IS NOT PERSISTED (verified absent)
  A direct scan of lib/core/background/ for private-field identifiers
  (contactName, displayName, locationText, eventTitle, taskTitle, notes)
  returns NOTHING. Worker input therefore carries no Contact names, Event
  titles, Task titles, descriptions, notes, location text, numeric
  coordinates, rendered notification strings or any other private content.

PRIVATE CONTENT IS REREAD AT DELIVERY TIME
  All private copy is produced at posting time by
  reminder_notification_renderer.dart from a fresh canonical source read
  performed by reminder_delivery_service.dart / reminder_delivery_source_reader
  through the live repositories. Nothing private survives in durable dispatch
  metadata. This is exactly why a Contact rename before delivery yields the
  current name and never a stale persisted one.
