D. DESCRIPTION PREVIEW (120 GRAPHEMES, GRAPHEME-SAFE)
================================================================================

File: reminder_notification_renderer.dart

  static const int maxDescriptionGraphemes = 120;
  static const String ellipsis = '…';

  static String descriptionPreview(String? description, {
    int maxGraphemes = maxDescriptionGraphemes,
  }) {
    final trimmed = description?.trim();
    if (trimmed == null || trimmed.isEmpty) return '';
    final graphemes = trimmed.characters;
    if (graphemes.length <= maxGraphemes) return trimmed;
    final keep = maxGraphemes - ellipsis.characters.length;
    return '${graphemes.take(keep)}$ellipsis';
  }

LAWS HELD
  - Counted in GRAPHEMES via package:characters, so combining marks, emoji ZWJ
    sequences and regional indicators are never split.
  - The ellipsis is INSIDE the 120-grapheme budget (keep = 120 - 1 = 119 plus
    the ellipsis = 120 total).
  - At or under the limit the text is returned completely unchanged.
  - The location URI/coordinate rejection rules are NOT applied to ordinary
    descriptions. Proven explicitly by D7c.
  - A description that is null/blank yields no line at all (never a filler).

H. HEADLESS RUNTIME DEFECT CORRECTION
================================================================================

File: lib/features/notifications/application/reminder_background_runtime.dart

DEFECT (inherited, not introduced this round)
  `diagnosticsProvider` and `startupRepositoryProvider` are declared to THROW
  until an app root overrides them. `StartupController.build()` reads
  `_diagnostics` before its first await, so any headless read reaching
  StartupController raised:

      ProviderException: Tried to use a provider that is in error state.
      Bad state: SanitizedDiagnostics must be overridden at the app root

  and the whole reconciliation failed closed.

MINIMUM CORRECTION
  One added override at the headless ProviderContainer:

      diagnosticsProvider.overrideWithValue(SanitizedDiagnostics()),

  Justification for the exact minimum:
    - `SanitizedDiagnostics` is pure Dart with no UI, plugin or profile
      dependency, so it is trivially safe in a WorkManager isolate.
    - `startupRepositoryProvider` is deliberately NOT overridden. The headless
      container already overrides `reminderRuntimeProfileIdProvider`, which
      `CalendarEventController._profileId` consults FIRST. Overriding the
      startup repository would pull UI startup semantics (open profile,
      migrate, seed) into the worker isolate, which this correction must not do.
    - No fake UI dependency was introduced.
    - StartupController and WorkManager design were not redesigned.
    - Fail-closed behaviour was NOT weakened.
    - Previously visible errors were NOT swallowed.

PROOF
  D28/D28b build the LEGACY container and reproduce the defect.
  D29/D30 prove the corrected container no longer crashes on the tested
  reconciliation path.
  D29b statically asserts the production source wires exactly
  `diagnosticsProvider.overrideWithValue` and does NOT wire
  `startupRepositoryProvider.overrideWith`.

  Remaining M7 regressions in the snooze suite are inherited (see section I).

File: android/app/src/main/res/drawable/ic_nt_notification.xml

METHOD: vector group reframing (NOT a coordinate rewrite).
A single <group> wraps the single, byte-identical path:

  <group android:scaleX="1.08" android:scaleY="1.08"
         android:translateX="-4.32" android:translateY="-4.32">
    <path android:fillColor="#FFFFFFFF"
          android:pathData="M89.15 21.32C89.89 ... 76.59 74.26Z" />
  </group>

The pathData is byte-identical to baseline. The diff is exactly:
  7 insertions(+), 1 deletion(-)

MEASURED GEOMETRY (viewport 108 x 108)
                 before      after
  width           88.9%   ->  96.0%
  height          62.4%   ->  67.4%
  margin left          -  ->  2.16
  margin right         -  ->  2.16
  margin top           -  ->  17.61
  margin bottom        -  ->  17.61

The scale is UNIFORM (1.08 / 1.08), so the mark is never stretched. The margin
is symmetric on every side, so the mark stays visually centred.

WHY 1.08 AND NOT MORE
  The artwork is width-bound: at 96.0 units wide inside a 108-unit viewport the
  maximum safe uniform scale is 104.0/96.0 = 1.0833. Beyond that the path clips
  the canvas. A larger height occupancy was investigated and found
  mathematically unreachable without clipping, because a uniform scale cannot
  change the artwork's aspect ratio. 1.08 is therefore the maximum conservative
  value that strictly improves occupancy with a clean 2.16-unit margin.

BOUNDARY RESPECTED
  - mipmap-*/ic_launcher.png NOT touched (verified: zero git entries).
  - No runtime icon-size API introduced.
  - No permission change.
  - Brand mark preserved; monochrome single-path fill suitable for tinting.
  - Automated geometry tests serve as regression protection only.
  - FINAL SUBJECTIVE ACCEPTANCE REMAINS OWNER PHYSICAL REVIEW ON THE INFINIX.
